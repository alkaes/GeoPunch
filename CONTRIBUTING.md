# Contributing

GeoPunch's source code is not public, so this repository doesn't take pull requests. You can still shape the app a lot:

- **Report bugs** with the [bug report](https://github.com/alkaes/GeoPunch/issues/new?template=bug_report.yml) form. A clear "what I did, what I saw, what I expected" with the version numbers is the most useful thing you can give.
- **Vote** with a 👍 on the issues you care about. Feature requests are prioritised by votes and by how many people they unblock.
- **Request features** with the [feature request](https://github.com/alkaes/GeoPunch/issues/new?template=feature_request.yml) form. Start from the problem you have, not the button you want.
- **Tell us about your server** with the [server compatibility](https://github.com/alkaes/GeoPunch/issues/new?template=server_compatibility.yml) form if GeoPunch doesn't work with it. OrangeHRM setups vary, and every report widens what's supported.
- **Translate**: corrections to Hebrew and Russian, and new languages, through the [translation](https://github.com/alkaes/GeoPunch/issues/new?template=translation.yml) form.
- **Test pre-releases** on Google Play: email alkaes@gmail.com to join.

## How issues are handled

1. New issues get the `needs-triage` label.
2. Triage adds a type label and, when something is missing, `needs-info`. Issues waiting for information for 30 days are closed; reopen them with the details any time.
3. Accepted issues are labelled `planned`, and closed with a link to the release that fixes them.
4. Ideas that don't fit GeoPunch are closed as `wontfix` with the reason.

## Ground rules

- Keep private data out: no server addresses, credentials, colleagues' names or exact locations. Anything posted here is public and indexed.
- Be kind. See the [code of conduct](CODE_OF_CONDUCT.md).
- One problem or idea per issue.
- GeoPunch isn't an OrangeHRM product. Questions about your company's OrangeHRM configuration belong with your HR administrator.
